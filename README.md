# レシわけ

レシートを撮り、リンクを送る。参加者が自分の品目を選ぶと、立て替えた人に返す金額が分かるWebアプリです。会員登録やアプリのインストールは不要です。

公開先: [レシわけ — reciwake.kotek7.com](https://reciwake.kotek7.com)

## 使い方

1. 支払った人がレシートを撮影するか画像を選びます。手入力でも始められます。
2. 読み取った品目・金額・合計を確認して、誤りを直し、精算の名前と自分の名前を入力します。
3. 作成した会計の共有リンクをLINEなどで送ります。
4. 参加者はリンクを開き、名前を入力して、自分の品目を選びます。支払った人も自分の品目を選びます。
5. 全員が選択を完了し、すべての品目の負担者が決まったら、支払った人が精算を確定します。
6. 各参加者が返す金額を確認し、支払った人が受け取りを記録します。

同じ品目を複数人が選ぶと均等に分けます。数量や負担割合が異なるときは、品目を別の行に分けてください。品目の合計とレシート合計に差がある場合は、各品目の金額に比例して差額を配分します。税額や割引を含め、最終的な負担額の合計がレシート合計と一致するよう円単位で調整します。

## ローカルで起動

Node.js **22.13以降**とnpmが必要です。永続化にNode.js標準の`node:sqlite`を使います。

```sh
npm install
npm run dev
```

[http://localhost:4317](http://localhost:4317) を開きます。ExpressがAPIとViteの開発画面を同じポートで提供します。

ビルド済み画面をローカルのExpressサーバーで配信:

```sh
npm run build
npm start
```

開発時の確認コマンド:

```sh
npm run check
npm test
```

| 環境変数   | 既定値    | 内容                 |
| ---------- | --------- | -------------------- |
| `PORT`     | `4317`    | HTTPポート           |
| `HOST`     | `0.0.0.0` | 待ち受けアドレス     |
| `DATA_DIR` | `./data`  | SQLiteデータの保存先 |

環境変数を指定する例:

```sh
PORT=4317 HOST=0.0.0.0 DATA_DIR=./data npm start
```

## ローカル版をスマートフォンで試す

PCとスマートフォンを同じネットワークにつなぎ、スマートフォンから`http://PCのLAN IP:4317`を開きます。共有リンクもスマートフォンから届くアドレスで作成してください。`localhost`のリンクは別の端末から開けません。接続できない場合はPCのファイアウォールとネットワークの端末間通信設定を確認してください。

撮影はブラウザ内で行います。カメラの利用にはHTTPS（または同じ端末のlocalhost）とカメラの許可が必要です。スマートフォンからLAN内のHTTPアドレスで開いた場合は「写真から選ぶ」を使うか、HTTPSの公開版で撮影してください。ネイティブ共有やクリップボードへのコピーにも安全な接続が必要な場合があります。使えない場合は、画面に表示した共有URLを選択してコピーできます。

## 写真の読み取り

日本語・英語のTesseract OCRをブラウザ内で実行します。レシート画像はサーバーへ送信しません。初回利用ではOCRの実行ファイルと言語データをCDNから取得するため、インターネット接続が必要です。

「レシートを撮る」は外部カメラアプリへ切り替えず、対応カメラでは静止画撮影と連続オートフォーカスを使用します。静止画APIが使えない場合は映像から写真を作成します。撮影後にカメラを停止してからOCRを開始します。撮影・選択した画像は192万画素以内に収め、縦長レシートの細かい文字を残せるよう長辺は3200pxまで保持します。OCR用画像はPNGにし、JPEGの追加圧縮による文字の劣化を避けます。確認画面にも同じ縮小済み画像を使用します。読み取りの同時実行を防ぎ、終了時にOCRワーカーを解放します。

薄い文字、傾き、折り目、複雑な税表記などは読み違えることがあります。共有前に品目と合計を確認し、必要に応じて編集してください。画像を正面から明るい場所で撮ると読み取りやすくなります。

## 共有と保存

会計ごとに`/r/ランダムなID`の共有URLを作成します。このURLを知る人は会計内容を閲覧し、名前を入力して参加できます。URLは参加者間で共有してください。

参加者本人の操作権限は、参加時に発行したトークンで確認します。トークンはそのブラウザの`localStorage`に保存され、同じブラウザから戻ると自分として操作を続けられます。ブラウザのデータ削除、別のブラウザ・端末への移動では元の参加者の権限を引き継げません。

精算の確定・再開と受け取りの記録は支払った人が行います。精算を再開すると支払済みの記録がクリアされるため、変更後の金額で確認し直してください。各自の品目選択と選択完了の状態は残ります。金銭の送金自体は行いません。

間違って参加した人や操作できなくなった参加者は、支払った人が「みんなの精算」から削除できます。精算が確定済みの場合は先に再開してください。削除すると、その人の品目選択と操作権限も取り消されます。立て替えた本人は削除できません。

保存先は実行環境ごとに異なります。

- Cloudflare版: 1つの会計につき1つのSQLite対応Durable Objectに保存します。
- ローカル・Docker版: `DATA_DIR/receipt-split.sqlite`に保存します。再起動後も保存先が残っていれば継続利用できます。データを保持するには`DATA_DIR`の内容を保持・バックアップしてください。

Cloudflare版とローカル版のデータ・参加権限は別々です。両者を自動で移行する機能はありません。

## Cloudflare

`wrangler.jsonc`にWorker `reciwake`、公開ドメイン`reciwake.kotek7.com`、静的ファイルとDurable Objectの設定を置いています。Viteで作った画面をWorkers Static Assetsで配信し、`/api`以下をWorkerへ渡します。Durable Objectは`ROOMS`バインディングの`ReceiptRoom`クラスを使います。

Cloudflare環境をローカルで起動:

```sh
npm run build
npm run dev:cloud
```

[http://localhost:8787](http://localhost:8787)を開きます。画面の変更を反映するには、もう一度`npm run build`を実行します。`wrangler dev`のローカルデータは、公開先やExpress版のデータとは別です。

起動中のCloudflareローカル環境のAPIを確認:

```sh
npm run test:cloud
```

このテストは動作確認用の会計を作成します。接続先は既定で`http://127.0.0.1:8787`です。

公開するには、`kotek7.com`を管理するCloudflareアカウントでWranglerにログインしてからデプロイします。

```sh
npx wrangler login
npm run build && npm run check:worker && npm run deploy
```

初回デプロイで、`wrangler.jsonc`のマイグレーション設定に従ってSQLite対応の`ReceiptRoom`を作成します。`PORT`・`HOST`・`DATA_DIR`はExpress版用の設定で、Cloudflare版では使いません。

## Docker

```sh
docker build -t receipt-split .
docker run --rm -p 4317:4317 -v receipt-split-data:/app/data receipt-split
```

コンテナはNode.js 24でExpress版を実行し、SQLiteを`/app/data`に保存します。名前付きボリューム`receipt-split-data`はコンテナの終了・再作成後も残ります。外部に公開する場合は、HTTPSを提供するリバースプロキシなどからこのHTTPサーバーへ接続してください。

## 構成

- `src/`: React・TypeScriptの画面、ブラウザ内OCR
- `server/`: ローカル・Docker用のExpress APIとSQLite永続化
- `worker/`: Cloudflare Worker APIとDurable ObjectのSQLite永続化
- `shared/`: フロントエンドとサーバーで共有する型・計算処理
- `tests/`: 精算やAPIなどのテスト
- `wrangler.jsonc`: Cloudflareの公開・ローカル実行設定

Express版のサーバーは`tsx`でTypeScriptを実行します。`npm run build`は型を確認し、Viteでフロントエンドを`dist/`へ出力します。Workerの型確認は`npm run check:worker`で実行します。
