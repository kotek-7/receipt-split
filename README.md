# レシわけ

家飲みの食材・お酒の買い出しや、居酒屋の会計を分けるWebアプリです。レシートを撮って人数を決め、リンクを送ります。それぞれが食べた・飲んだ分だけタイルを選ぶと、みんなで分ける料理代も含めて、立て替えた人に返す金額が分かります。会員登録やアプリのインストールは不要です。

公開先: [レシわけ — reciwake.kotek7.com](https://reciwake.kotek7.com)

## 使い方

1. 買い出し代や居酒屋の会計を立て替えた人が、レシートを撮影するか写真を選びます。手入力でも始められます。
2. 料理・飲み物・食材の数量と金額を確認し、飲み会の名前・自分の名前・割り勘人数を入力します。人数は立て替えた人を含めて1〜100人、金額はその行の数量すべての合計です。
3. 共有リンクを飲み会のメンバーへLINEなどで送ります。
4. それぞれが名前を入力し、自分のドリンクなど、食べた・飲んだ分だけタイルを選びます。1つのタイルが1杯・1品にあたり、もう一度押すと取り消せます。立て替えた人も選びます。みんなで分ける料理・食材は最初の人数で割って自動で加算されるため、参加者が選ぶ操作はありません。
5. 自分の入力を完了すると、自分の分、または立て替えた人に返す金額を表示します。「選び直す」で入力に戻れます。ほかの人の参加や入力で自分の金額は変わらず、そのまま精算できます。
6. 立て替えた人は同じ画面の「参加状況」で確認します。指定した人数がそろい、全員が入力を完了して数の残りがなくなったら入力を締め切り、「受け取り状況」で受け取ったお金を記録します。

作成画面でも、購入数量を1杯・1品ずつのタイルで確認できます。「＋」で増やし、タイルを押すと1つ減ります。数量は1〜999で、タイルは12個まで表示し、それを超えた数をまとめて示します。「数で入力」を開けば直接変更でき、数量を変えても入力済みの合計金額は変わりません。

## 金額の計算

新しく作る会計では、最初の人数と本人が入力した数量で金額が決まります。

- 自分のドリンクなどは、レシートの行の合計金額を購入数量で割り、本人の数量を掛けます。生ビール3杯・計1,800円なら、1杯600円です。購入数量を超えて選ぶことはできず、誰も選んでいない数は残りとして表示します。ほかの人の分は人物マークで示し、選択できません。13個以上の品は12個ずつ追加表示でき、数を直接入力することもできます。
- みんなで分ける料理・食材は、行の合計金額を最初の割り勘人数で割り、全員の金額に含めます。唐揚げ1皿・1,200円を4人で分けるなら、1人300円です。まだ参加していない人の分は、その人が参加するまで未割り当ての金額として残します。

この例でビールを1杯飲んだ人は、ビール600円＋唐揚げ300円の**900円**を負担します。ほかの人が参加したり数量を変更したり、立て替えた人がほかの参加者を削除したりしても、本人の数量が同じなら金額は変わりません。両方の分け方を同じレシートで組み合わせられます。

入力した行の合計と実際の会計額に差がある場合は、まず各行の金額に比例して税・値引きなどを割り当てます。その後、各行を購入数量または最初の人数で割り、1円未満を切り捨てます。各行で割り切れずに残った分は、立て替えた人の負担にまとめて加算します。端数の負担も他の人の入力に左右されません。全員が参加して購入数量をすべて割り当てると、全員の負担額の合計が実際の会計額と一致します。

この計算は、作成APIに`calculationMode: "fixed-participants"`と`participantCount`を渡して作成した会計に適用します。画面から新しく作る会計はこの方式です。この設定がない既存の会計は従来の計算を保ち、分け合う料理を選んだ人で均等に分けます。旧方式で品目の分け方が未設定の場合も、その品を選んだ人で均等に分けます。

## ローカルで起動

Node.js **22.13以降**とnpmが必要です。永続化にNode.js標準の`node:sqlite`を使います。

```sh
npm install
npm run dev
```

[http://localhost:4317](http://localhost:4317) を開きます。ExpressがAPIとViteの開発画面を同じポートで提供します。

ビルド済み画面をローカルのExpressサーバーで配信:

```sh
npm run build
npm start
```

開発時の確認コマンド:

```sh
npm run check
npm test
```

| 環境変数   | 既定値    | 内容                 |
| ---------- | --------- | -------------------- |
| `PORT`     | `4317`    | HTTPポート           |
| `HOST`     | `0.0.0.0` | 待ち受けアドレス     |
| `DATA_DIR` | `./data`  | SQLiteデータの保存先 |

環境変数を指定する例:

```sh
PORT=4317 HOST=0.0.0.0 DATA_DIR=./data npm start
```

## ローカル版をスマートフォンで試す

PCとスマートフォンを同じネットワークにつなぎ、スマートフォンから`http://PCのLAN IP:4317`を開きます。共有リンクもスマートフォンから届くアドレスで作成してください。`localhost`のリンクは別の端末から開けません。接続できない場合はPCのファイアウォールとネットワークの端末間通信設定を確認してください。

撮影はブラウザ内で行います。カメラの利用にはHTTPS（または同じ端末のlocalhost）とカメラの許可が必要です。スマートフォンからLAN内のHTTPアドレスで開いた場合は「写真から選ぶ」を使うか、HTTPSの公開版で撮影してください。ネイティブ共有やクリップボードへのコピーにも安全な接続が必要な場合があります。使えない場合は、画面に表示した共有URLを選択してコピーできます。

## 写真の読み取り

Cloudflare 版では、画像対応モデル Gemma 4 で品名・数量・行金額・支払総額をまとめて読み取ります。写真を選ぶ前に送信先を表示し、「端末内で読み取る」へ切り替えられます。AI 読み取りでは縮小した写真を Cloudflare Workers AI に送信します。アプリは画像やモデルの生応答をログ・データベースへ保存せず、共有リンクにも画像を含めません。AI の失敗時には同じ写真を端末内で読み直せます。

端末内の読み取りは日本語・英語の Tesseract OCR を使い、写真を送信しません。初回は OCR 本体と言語データを CDN から取得します。通常の `npm run dev` はこの方式のみで動きます。Cloudflare 版の AI 接続も含めて確認する場合は `npm run build && npm run dev:cloud` を使います。AI binding はローカル開発でも Cloudflare に接続し、アカウントの利用量に含まれます。

AI の応答はサーバーで型・金額・数量を検証し、印字された行金額に数量を掛け直しません。読めない金額や数量は入力を求め、明細・税・値引きと総額の不一致も表示します。合計に合わせた架空の商品は追加しません。API は画像 8 MB・長辺 3200 px・192 万画素まで、同一オリジン、1 IP あたり 6 回/分、45 秒の上限があります。新しい API キーの登録は不要で、Worker の `AI` binding を使用します。

「レシートを撮る」は外部カメラアプリへ切り替えず、対応カメラでは静止画撮影と連続オートフォーカスを使用します。静止画APIが使えない場合は映像から写真を作成します。撮影後にカメラを停止してからOCRを開始します。撮影・選択した画像は192万画素以内に収め、縦長レシートの細かい文字を残せるよう長辺は3200pxまで保持します。OCR用画像はPNGにし、JPEGの追加圧縮による文字の劣化を避けます。確認画面にも同じ縮小済み画像を使用します。読み取りの同時実行を防ぎ、終了時にOCRワーカーを解放します。

暗い背景に白いレシートがある写真では、小さな解析画像から紙の範囲を見つけ、周囲の模様を除いて読み取ります。紙を区別できない画像や複数の紙が写る場合は、画像全体を使います。解析画像は本読み取りの前に解放し、切り出した画像にも同じ画素数上限を適用します。

端末内の読み取りでも、商品名の下の「3コ×単138」「3杯×@580」「@580×3杯」のような数量・単価を直前の商品と組み合わせます。印字された行金額を優先し、行金額がなく数量と単価が明確な場合だけ掛け算で求めます。「2, 973」のような桁区切りの空白にも対応します。

薄い文字、傾き、折り目、複雑な税表記などは読み違えることがあります。共有前にレシートの内容と合計を確認し、必要に応じて編集してください。画像を正面から明るい場所で撮ると読み取りやすくなります。

日本語の公開実写・合成レシートを固定版から取得し、同じ画像で改善前後を比較しています。[取得方法とライセンス](scripts/receipt-datasets/README.md)、[評価の実行方法](scripts/receipt-eval/README.md)、[手法の調査と測定結果](docs/receipt-recognition-research.md)を参照してください。

## 共有と保存

会計ごとに`/r/ランダムなID`の共有URLを作成します。このURLを知る人は会計内容を閲覧し、名前を入力して参加できます。URLは参加者間で共有してください。

作成時の割り勘人数を超えて参加することはできません。参加済みの人数は画面上部、入力完了の人数は立て替えた人の「参加状況」で確認できます。人数を設定する機能の追加前に作成した会計は、従来どおり参加済みの全員を対象に割り勘します。

参加者本人の操作権限は、参加時に発行したトークンで確認します。トークンはそのブラウザの`localStorage`に保存され、同じブラウザから戻ると自分として操作を続けられます。ブラウザのデータ削除、別のブラウザ・端末への移動では元の参加者の権限を引き継げません。

全員の入力の締め切り・解除と受け取りの記録は立て替えた人が行います。締め切り後は数量などを変更できません。締め切りを解除すると受け取り済みの記録がクリアされるため、変更後の金額で確認し直してください。それぞれが選んだ内容と入力完了の状態は残ります。金銭の送金自体は行いません。

間違って参加した人や操作できなくなった参加者は、立て替えた人が「参加状況」から削除できます。入力を締め切った後は先に締め切りを解除してください。削除すると、その人が選んだ内容と操作権限も取り消されます。立て替えた本人は削除できません。

保存先は実行環境ごとに異なります。

- Cloudflare版: 1つの会計につき1つのSQLite対応Durable Objectに保存します。
- ローカル・Docker版: `DATA_DIR/receipt-split.sqlite`に保存します。再起動後も保存先が残っていれば継続利用できます。データを保持するには`DATA_DIR`の内容を保持・バックアップしてください。

Cloudflare版とローカル版のデータ・参加権限は別々です。両者を自動で移行する機能はありません。

## Cloudflare

`wrangler.jsonc`にWorker `reciwake`、公開ドメイン`reciwake.kotek7.com`、静的ファイルとDurable Objectの設定を置いています。Viteで作った画面をWorkers Static Assetsで配信し、`/api`以下をWorkerへ渡します。Durable Objectは`ROOMS`バインディングの`ReceiptRoom`クラスを使います。

Cloudflare環境をローカルで起動:

```sh
npm run build
npm run dev:cloud
```

[http://localhost:8787](http://localhost:8787)を開きます。画面の変更を反映するには、もう一度`npm run build`を実行します。`wrangler dev`のローカルデータは、公開先やExpress版のデータとは別です。

起動中のCloudflareローカル環境のAPIを確認:

```sh
npm run test:cloud
```

このテストは動作確認用の会計を作成します。接続先は既定で`http://127.0.0.1:8787`です。

ローカル環境の起動からAPIの検証、終了までまとめて実行する場合:

```sh
npm run build
npm run test:cloud:local
```

一時的な保存先でWranglerを起動し、既存のローカルデータや公開環境に会計を作らずに検証します。

## CI / CD

[GitHub Actions](https://github.com/kotek-7/receipt-split/actions/workflows/ci.yml)で、push・Pull Request・手動実行時にNode.js 24で以下を確認します。

- `npm ci`によるロックファイルからの依存インストール
- フォーマットとWorkerの型チェック
- 単体・API・画面テスト
- アプリの型チェックとフロントエンドのビルド
- 一時的なCloudflareローカル環境でのAPI操作テスト

CIにCloudflareの認証情報は不要です。

すべての検証が成功すると、既定ブランチ（現在は`codex/receipt-split`）へのpushをCloudflare本番環境に自動デプロイします。PRやほかのブランチからは公開しません。既定ブランチを選んで手動実行した場合も、同じ検証とデプロイを行います。

デプロイは1件ずつ実行します。開始時に既定ブランチの最新コミットを確認し、古いコミットの再実行によって本番が巻き戻らないようにします。公開後はトップページと`/api/health`を確認します。会計を作成するAPI操作テストはローカル環境で実行します。

自動デプロイの初回設定:

1. [CloudflareのAccount API tokens画面](https://dash.cloudflare.com/?to=/:account/api-tokens)で公開先アカウントのトークンを作成します。カスタム権限で、指定したWorker `reciwake`に`Individual Workers Editor`、指定したドメイン`kotek7.com`に`Zone Read`と`Workers Routes Edit`（確認画面では`Workers Routes Write`）を設定します。この設定で既存Workerの更新を確認しています。Workerや独自ドメインを新規作成・変更する場合の権限と制限は、[Cloudflare公式の権限説明](https://developers.cloudflare.com/workers/authorization/workers/)を参照してください。
2. [リポジトリのActions Secrets](https://github.com/kotek-7/receipt-split/settings/secrets/actions)に`CLOUDFLARE_API_TOKEN`を登録します。トークンをコードやコミットに含めないでください。
3. [Actions Variables](https://github.com/kotek-7/receipt-split/settings/variables/actions)に、公開先アカウントのIDを`CLOUDFLARE_ACCOUNT_ID`として登録します。
4. Actionsの`CI / CD`から`Run workflow`で既定ブランチを実行します。

トークンまたはアカウントIDが未設定の場合、検証ジョブは実行され、デプロイジョブに設定不足のエラーが表示されます。設定後はその実行を再実行できます。デプロイ設定は`wrangler.jsonc`と共通です。

## 手動デプロイ

公開するには、`kotek7.com`を管理するCloudflareアカウントでWranglerにログインしてからデプロイします。

```sh
npx wrangler login
npm run build && npm run check:worker && npm run deploy
```

初回デプロイで、`wrangler.jsonc`のマイグレーション設定に従ってSQLite対応の`ReceiptRoom`を作成します。`PORT`・`HOST`・`DATA_DIR`はExpress版用の設定で、Cloudflare版では使いません。

## Docker

```sh
docker build -t receipt-split .
docker run --rm -p 4317:4317 -v receipt-split-data:/app/data receipt-split
```

コンテナはNode.js 24でExpress版を実行し、SQLiteを`/app/data`に保存します。名前付きボリューム`receipt-split-data`はコンテナの終了・再作成後も残ります。外部に公開する場合は、HTTPSを提供するリバースプロキシなどからこのHTTPサーバーへ接続してください。

## 構成

- `src/`: React・TypeScriptの画面、ブラウザ内OCR
- `src/tokens.css`: 色・文字・余白などの共通値。画面のルールは[デザインシステム](docs/design-system.md)を参照
- `server/`: ローカル・Docker用のExpress APIとSQLite永続化
- `worker/`: Cloudflare Worker APIとDurable ObjectのSQLite永続化
- `shared/`: フロントエンドとサーバーで共有する型・計算処理
- `tests/`: 割り勘やAPIなどのテスト
- `wrangler.jsonc`: Cloudflareの公開・ローカル実行設定

Express版のサーバーは`tsx`でTypeScriptを実行します。`npm run build`は型を確認し、Viteでフロントエンドを`dist/`へ出力します。Workerの型確認は`npm run check:worker`で実行します。
